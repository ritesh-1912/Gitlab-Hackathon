# Demo Runbook: DuoGate

This document provides a step-by-step runbook for the automated DevSecOps scenarios in `DuoGate`.

> [!NOTE]
> All demo branches are pushed to GitLab only. Ensure your local repository has the `gitlab` remote configured pointing to your GitLab project:
> ```bash
> git remote add gitlab https://gitlab.com/gitlab-ai-hackathon/transcend-october-2026/43738285/showcase
> ```

---

## Pre-Flight Setup & Governance Baseline

### 1. Honest Scope, Limitations & Fixture Notes
- **Advisory Flows vs. CI Gate**: GitLab Duo custom flows are advisory and operate strictly within the available platform tools (`get_issue`, `get_repository_file`, `list_repository_tree`, `create_issue_note`). They do not autonomously block merges. The deterministic **CI Accountability Gate** (`accountability-gate` job in `.gitlab-ci.yml`) is what strictly enforces provenance trailers and issue intent linkage.
- **Forward-Looking Provenance**: AI origin cannot be retrospectively identified in legacy commits without metadata. DuoGate establishes an enforceable contract *going forward*.
- **Incident Remediation**: Incident issues are opened by a human from the template (`.gitlab/issue_templates/incident.md`) upon observing staging healthcheck failures.
- **Demo Commit Provenance**: Provenance trailers on demo branch commits (`Assisted-by: gitlab-duo`) are scripted test fixtures generated by `./scripts/seed_demo.sh`, not commits authored by Duo.

### 2. How to Invoke the Flows
To register and trigger custom flows in GitLab:
1. Open the project in GitLab and navigate to **AI > Flows** (or **Automate > Flows**).
2. Create a **New flow** by pasting the corresponding YAML file from `flows/` and adding a **Mention** trigger. Note the generated service account handle (e.g. `@ai-...`).
3. To invoke a flow, post a comment on an issue or merge request mentioning its service account handle, and include the branch name and issue number (e.g., `@ai-accountability-card-gitlab-ai-hackathon review branch demo/scenario-a-clean for issue #2`).

### 3. Submission Flow Execution Status
- **Accountability Card** (`flows/accountability-card.yml`): Executed on Issue #2 using service account `@ai-accountability-card-gitlab-ai-hackathon` for branch `demo/scenario-a-clean`.
- **Tracer Bullet** (`flows/tracer-bullet.yml`): Mention trigger successfully started a Duo session, but output did not match the intended behavior; it is evaluated strictly as a trigger-wiring smoke test, not as working as designed.
- **Intent Flow** (`flows/intent.yml`): Defined in `flows/` but NOT executed for this submission.
- **Incident Trace Flow** (`flows/incident-trace.yml`): Defined in `flows/` but NOT executed for this submission.

### 1. Plan Stage: Define Intent
1. In GitLab, create Issue #2 titled `Add Inventory Summary Endpoint`.

### 2. Push Branch & Create Merge Request
1. Push the clean branch to GitLab:
   ```bash
   git push -u gitlab demo/scenario-a-clean
   ```
2. Open Merge Request !1 on GitLab with these exact details:
   - **Title**: `feat: add inventory summary endpoint`
   - **Description**: `Implements aggregated inventory summary calculation. Closes #2`

### 3. Review Stage: Accountability Card Invocation
1. On Issue #2, invoke the Accountability Card flow by mentioning its handle:
   ```text
   @ai-accountability-card-gitlab-ai-hackathon please review branch demo/scenario-a-clean for issue #2
   ```

### 4. Observed Result
- **Accountability Card Session**:
  - Mentioning `@ai-accountability-card-gitlab-ai-hackathon` started a Duo session (approx. 2 minutes) that posted a review card to Issue #2.
  - **Recommendation**: `APPROVE with conditions`
  - **Risk**: `LOW`
  - **Findings**: The agent correctly identified `GET /inventory/summary` returning `total_items` and `total_quantity` and noted a test using loose bounds.
  - **Platform Tool Limitations Reported by Agent**: The agent honestly reported that it could NOT verify the `Assisted-by` trailer (no commit-message tool available), could not inspect the git diff directly, and noted that `gate_report.json` was not present in the repository (as it is a gitignored CI pipeline build artifact).
- **MR Pipeline #2994044219**:
  - All MR jobs passed: `test`, `semgrep-sast`, `secret_detection`, and `accountability-gate`.
- **Merge & Default Branch Pipeline #2994050055**:
  - MR !1 merged cleanly into `main`.
  - Issue #2 was automatically closed by GitLab via `Closes #2`.
  - Main pipeline #2994050055 passed: `test` (57 tests passing), `semgrep-sast`, `secret_detection`, `accountability-gate`, `pages` (deploy to staging), and `staging-healthcheck`.
  - Continuous Accountability Ledger updated live on GitLab Pages at [https://showcase-6f05ac.gitlab.io](https://showcase-6f05ac.gitlab.io), indexing compliant provenance entries.
