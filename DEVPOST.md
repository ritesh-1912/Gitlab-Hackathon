## 💡 Inspiration

Generative AI has fundamentally solved code authoring. Code assistants can author functions, microservices, and unit tests in seconds. But as teams ship AI-assisted code at unprecedented velocity, software delivery faces a new, dangerous bottleneck: **the governance, traceability, and incident triage vacuum**.

When a production incident occurs, organizations cannot answer fundamental questions:
- *Where did this change come from? (A human, a chat prompt, or an autonomous background agent?)*
- *What specific requirement was it authorized to fulfill?*
- *When an outage occurs, can we trace the failure back to the responsible commit, developer intent, and MR?*

We built **`DuoGate`** to prove that **"Life After Code"** must focus on **governance, provenance, and rapid incident triage**. By combining automated, non-bypassable CI pipeline gates with the GitLab Duo Agent Platform, we transform unvetted AI code generation into a transparent, verifiable DevSecOps lifecycle.

## 🛠️ What It Does

`DuoGate` establishes a multi-layered DevSecOps governance system comprising a deterministic CI accountability gate, a continuous static Accountability Ledger hosted on GitLab Pages, and custom GitLab Duo flows that assist human operators across the lifecycle:

1. **Mandatory Provenance Contracts**:
   - Every commit must include an RFC-compliant Git trailer: `Assisted-by: <tool|agent>` or `Assisted-by: none`. (Note: demo commit trailers are scripted test fixtures generated by `./scripts/seed_demo.sh`, not commits authored by Duo).
   - Every Merge Request must link to a verified issue intent: `Closes #<id>` or `Fixes #<id>`.
2. **Automated CI Accountability Gate (`scripts/accountability_gate.py`)**:
   - Inspects commits introduced by the MR (`base..head`), explicitly excluding merge commits.
   - Enforces valid `Assisted-by:` trailers and issue intent linkage.
   - Ingests GitLab Secret Detection reports (`gl-secret-detection-report.json`) and halts merges on exposed credentials.
   - Supports a default-branch push mode that evaluates `CI_COMMIT_BEFORE_SHA..CI_COMMIT_SHA` (or `HEAD` if initial push). Commits at or before `ACCOUNTABILITY_BASELINE_SHA` (`e9672c8`) are grandfathered as pre-contract baseline.
   - Generates a structured `gate_report.json` artifact and fails non-compliant builds.
3. **Continuous Accountability Ledger on GitLab Pages (`scripts/build_ledger.py`)**:
   - Reconstructs the complete provenance audit trail directly from Git commit history.
   - Calculates provenance compliance rates, AI vs. human commit ratios, and active gate status.
   - Classifies merge commits as "Merge (excluded)" and baseline starter commits as "Grandfathered (pre-contract)", computing compliance over evaluated commits.
   - Published statically to GitLab Pages (`staging` environment) with zero external database dependencies, accessible at [https://showcase-6f05ac.gitlab.io](https://showcase-6f05ac.gitlab.io).
4. **GitLab Duo Custom Flows**:
   - **Advisory by Design**: Flows operate within available platform tools (`get_issue`, `get_repository_file`, `list_repository_tree`, `create_issue_note`). They do not autonomously block merges; the CI accountability gate strictly enforces rules.
   - **Accountability Card (`flows/accountability-card.yml`)**: Triggered via comment mention (`@ai-accountability-card-gitlab-ai-hackathon`). Evaluates repository files and issue context, posting an advisory review card rating risk and recommending APPROVE/REJECT.
   - **Tracer Bullet (`flows/tracer-bullet.yml`)**: Trigger-wiring smoke test verifying mention event dispatch.
   - **Intent Definition (`flows/intent.yml`) & Incident Trace (`flows/incident-trace.yml`)**: Custom flows defined for planning guardrails and post-incident rollback commands.

## 🤖 How We Built It & Used the GitLab Duo Agent Platform

We designed `DuoGate` using the official **GitLab Duo Agent Platform Flow Registry v1 ambient specification**:

- **Strict Ambient Schema Compliance**:
  - Our custom flows strictly adhere to Flow Registry v1 syntax: `version: "v1"`, `environment: ambient`, top-level `components`, `prompts`, `routers`, and `flow: { entry_point: ... }`.
  - We strictly omitted restricted keys (`name`, `description`, `product_group` at top level; `model`, `stop` in prompts).
- **Realistic Toolset Utilization & Honest Reporting**:
  - Operating within confirmed platform tools (`get_issue`, `get_repository_file`, `list_repository_tree`, `create_issue_note`).
  - When invoked on Issue #2 with the branch context, the Accountability Card flow completed an advisory review session in ~2 minutes, correctly highlighting new endpoints while honestly stating that it could not inspect git commit messages or git diff directly.
- **Supervised Autonomy by Design**:
  - Flows do not unilaterally push code or merge branches. Every output emphasizes: **"Advisory only: a human decides."**

## 🔄 DevSecOps Lifecycle Stages Covered

`DuoGate` covers 7 of GitLab's 9 lifecycle stages (plan, create, verify, secure, release, monitor, govern) plus incident remediation:

```
[PLAN]       Flow 1 (Intent Definition) establishes acceptance criteria & out-of-scope boundaries
   │
[CREATE]     Developer creates code with mandatory `Assisted-by:` trailers & `Closes #` links
   │
[VERIFY]     Pytest suite (57 tests) + Flow 2 (Accountability Card) assessing intent match & scope creep
   │
[SECURE]     GitLab SAST (semgrep) & Secret Detection scanning in MR pipeline + gate ingestion
   │
[RELEASE]    GitLab CI deploy job registering environment `staging` on default branch
   │
[GOVERN]     Accountability Gate enforcement + continuous Accountability Ledger on GitLab Pages
   │
[MONITOR]    In-process staging healthcheck smoke test runner (`scripts/smoke_test.py`)
   │
[REMEDIATE]  Flow 3 (Incident Trace) isolating culprit commit & outputting instant `git revert`
```

## 🚧 Challenges We Encountered

1. **CI Test Isolation**: Initial CI runs experienced test leakage where GitLab CI environment variables (`CI_PIPELINE_SOURCE=push`) caused unit tests to select push mode unexpectedly. We resolved this cleanly with an autouse `clean_ci_environment` fixture in `tests/conftest.py`.
2. **Ledger Classification of Merge and Starter Commits**: The continuous ledger previously marked the merge commit and the GitLab initial starter commit as missing trailers (88.9% compliance). We enhanced `scripts/build_ledger.py` to parse parents via `%P` and resolve `ACCOUNTABILITY_BASELINE_SHA`, classifying them as "Merge (excluded)" and "Grandfathered (pre-contract)" and achieving 100.0% compliance over evaluated commits.
3. **Flow Registry Tool Limits**: Custom flows currently lack native git commit trailer or git diff inspection tools. We adapted our prompts to operate honestly within confirmed tools (`get_issue`, `get_repository_file`, `list_repository_tree`), relying on the deterministic CI gate for non-bypassable enforcement.
4. **Honest Stated Limitation**: AI generation origin cannot be reliably detected retrospectively in legacy Git commits. We solved this by clearly documenting this constraint and establishing an enforceable, forward-looking provenance contract.

## 🎓 What We Learned

- **Complementary Roles of CI Gates and AI Agents**: AI agents excel at synthesizing context, drafting acceptance criteria, and flagging qualitative scope creep, but hard governance (blocking unverified code, credentials, or broken intent links) must remain anchored in deterministic CI pipeline gates.
- **Ambient Flow Authoring**: Designing flows under the Flow Registry v1 ambient specification requires strict adherence to allowed schema keys and toolsets.
- **Auditability via Native Git**: Leveraging RFC-compliant Git trailers (`Assisted-by:`) and static site publishing via GitLab Pages creates a resilient audit ledger with zero external database dependencies.
